## 1. アプリの目的と本質的な悩み

「忘れる前に気づかせる」共同タスク管理アプリ。自分のスマホと会社のPCの両方から、同じ予定・メモを入れられる。

利用者の物忘れの傾向（元の要件定義書より）と、それに対応する機能：

| 傾向 | 対応する機能 |
|---|---|
| 1. 認識しているのに、実行するタイミングで忘れる | 時間のリマインド、種類ごとの通知プリセット、繰り返し、「完了しましたか？」の確認 |
| 2. 注意が逸れると、元の目的が消える | 買い物リスト、持ち物チェック（「お店を出る時」は買い物完了で自動表示） |
| 3. 記録する前に流れる | ひとことメモ（すぐメモ）、メモを見る、何も書かずに保存したメモへの段階的なお知らせ |

グループ（家族・チームなど）では、**各メンバーが今何の仕事をしているかを把握できる** ことがねらい。

## 2. 利用者の好み・決まりごと（必ず守る）

### 2.1 画面の文言
- 画面の文言は日本語。**カッコ書きの説明は使わない**（例：×「日付なし（いつか）」→ ○「日付なし」）。日付の曜日「11月18日（水）」だけは例外
- **見れば分かることは説明しない**。補足文・案内文は最小限にする
- 押せることが分かる見た目にして、説明文で補わない

### 2.2 見た目
- 参考サイト：mindmarket.com（利用者がスクリーンショットで提示）
- 色（スクリーンショットから抜き出した値。`app/globals.css` の `:root`）

| 役割 | 色 |
|---|---|
| メインの緑 | `#8ED462` |
| クリーム（背景） | `#F5F1E4` |
| 文字 | `#2C2E2A` |
| 黄 | `#F5E211` |
| コーラル | `#FF705D` |
| 青 | `#2BA0FF` |
| ライラック | `#EBC1FF` |
| ピーチ | `#FFBE9F` |
| 茶 | `#BF5622` |

- 構成：クリームの背景に白いカードを浮かべる。ボタンは角丸＋右に白い丸のアイコン。メニューは緑の丸ボタン
- イラスト：丘・雲・太陽・テント・木の線画（`components/Icon.tsx` の `Scene`）でアウトドア感
- フォント：**Noto Sans JP**。基本は SemiBold(600)、大きな見出しだけ Bold(700)。`next/font` でアプリと一緒に配信
- 絵文字：**影のない、のっぺりした2Dイラスト**を自前で描いたもの（`components/Emoji.tsx`）。端末の絵文字は使わない（プッシュ通知の文面だけは端末任せ）
- 付箋の見た目（緑の全画面＋付箋を並べる）は、朝の「今日の予定」「メモを見る」「買い物リスト」「持ち物チェック」「今日の振り返り」で共通

### 2.3 作業の進め方
- 利用者はスマホから操作していることが多い。手順はスマホでできる形で案内する
- 返事は日本語。結論を先に、短く
- 変更ごとにブランチへコミットし、**プルリクエストを作って URL を伝える**。マージは利用者が行う
- デモ（アーティファクト）も毎回更新して URL を伝える
- 秘密の値（鍵・合言葉・接続文字列）は Git に入れない

## 3. 構成・デプロイ

### 3.1 技術
- Next.js 15（App Router）＋ React 19 ＋ TypeScript
- DB：Postgres（Neon）。ドライバは `pg`
- プッシュ通知：Web Push（`web-push`、VAPID）
- ホスティング：Vercel
- PWA：`public/manifest.webmanifest`、`public/sw.js`

### 3.2 リポジトリ
- GitHub：`ryodai426/Test`。**既定のブランチは `master`**
- リポジトリ直下には別アプリ「発明日記」（`index.html` ほか）がある。わすれないYO は `todo/` に独立して置いている
- 直下の `.vercelignore` は `/docs` だけ（`todo` を入れると、todo のビルドが空になって失敗する。過去に一度発生）
- 直下の `vercel.json` は発明日記用。`/todo/*` へのアクセスを発明日記のトップへ転送して、ソースを見せないようにしている

### 3.3 Vercel（設定済み）
- プロジェクト名：`todo`、**Root Directory：`todo`**
- 本番URL：https://todo-rho-navy-69.vercel.app
- Neon は Vercel の Storage から追加済み（接頭辞 `DATABASE` → `DATABASE_URL`）
- 環境変数（値は Vercel にだけある）：`DATABASE_URL`、`VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT`（アプリのURL）、`CRON_SECRET`
- アプリは `DATABASE_URL` のほか `POSTGRES_URL` や「接頭辞_DATABASE_URL」も探す（`lib/db.ts` の `databaseUrl()`）
- 表（テーブル）は **初回アクセス時に自動で作成・追加** される（`lib/schema.ts` を実行。版が同じなら確認の1往復だけ）。手作業の SQL は不要
- 設定の確認ページ：`/api/health`（接続先・DB・表・通知の鍵・サーバーとDBの場所・往復時間）

### 3.4 まだ済んでいない設定
- **毎分の呼び出し（cron）が未設定**。時間どおりのプッシュ通知（リマインド、未記入メモ、「完了しましたか？」、12時のメモ、20時の振り返り、持ち物チェック）はこれが前提。→ 9章の課題1を先に解決すること
- **Vercel の Function Region がアメリカ（初期値）のままの可能性**。`/api/health` で確認し、Neon と同じ地域（Tokyo / Singapore）にすると速くなる

## 5. データ（`lib/schema.ts`）

| 表 | 内容 |
|---|---|
| `users` | 名前（一意）、タイムゾーン、`review_skip`（夕方の振り返りを聞かない） |
| `sessions` | 端末ごとのログイン（トークンのハッシュ）。使うたびに期限延長（180日） |
| `link_codes` | 別の端末を追加する6桁コード（10分・1回限り） |
| `auth_failures` | 6桁コードの総当たり対策（10回失敗で10分止める） |
| `groups` | グループ。個人グループは登録時に自動作成。`invite_token`、作成・完了のお知らせ設定 |
| `memberships` | グループのメンバー |
| `tasks` | 予定とタスクとメモを1つの表に。下に主な列 |
| `task_kinds` | グループごとに自分たちで足した種類（メンバーで共有） |
| `task_done` | 繰り返し予定の「その日の分」の完了（完了時刻つき） |
| `task_items` | 買い物の品目。`checked_by` / `checked_at`（誰がチェックしたか） |
| `task_followups` | 「完了しましたか？」への返事。`snoozed`（まだ・15分後）／`held`（保留） |
| `reactions` | 完了への絵文字（👍❤️💪👏） |
| `checklists` / `checklist_items` / `checklist_checks` | 持ち物チェック。チェックはその日だけ有効（毎日リセット） |
| `notifications` | アプリ内のお知らせ（作成・完了・反応） |
| `push_subscriptions` | 端末ごとのプッシュ購読 |
| `sent_reminders` | 同じ通知を二重に送らないための記録（3日で消す） |
| `app_meta` | スキーマの版 |

`tasks` の主な列：
- `status`：`draft`（メモ）／`ready`（予定・タスク）
- `kind`：`general` / `meeting` / `duty` / `shopping` / `reminder`。`kind_id` があれば自分たちで足した種類（このとき `kind` は `general`）
- `date`、`time`（`HH:MM`、null なら終日）、`duration_min`
- `reminders`：`eve`（前日20:00）、`60`、`30`、`10`、`5`、`0`（分前）
- `repeat`：`{freq: daily|weekly|monthly, interval, weekdays, monthMode: day|nth, until}`
- `assignees`：表示する人（ユーザーIDの配列）。**NULL ＝ 共通（グループの全員）**。個人グループでは常に NULL
- `starred`：星マーク。`remind_all`：共通の予定で全員にもリマインド
- `done_at` / `done_by`：繰り返しでない予定の完了

## 7. 画面と機能の仕様（現在の実装）

### 7.1 ログインと端末
- 1台目：名前を入れてはじめる（パスワードなし）
- 2台目：1台目の「設定 → ほかの端末で使う」で出る6桁コードを「コードでログイン」に入力
- 招待リンク（`/?join=<token>`）を開いて登録すると、そのグループに入る

### 7.2 ホーム（カレンダー）
- DAY / WEEK / MONTH。スマホはツールバー2段（日付と前後、下に切り替え）
- **PC の DAY**：午前（0〜12時）と午後（12〜24時）の2列で、スクロールなしに1日を表示。正午をまたぐ予定は午後側に「続き」
- **空いている欄を長押し（PC は押したまま）して上下になぞる** と30分刻みで範囲を選べる。離すとその時間と長さで入力画面。端では自動スクロール。長押ししなければスクロール。軽く押すと押した位置（30分刻み）から1時間
- 予定の左の丸ボタンで、入力画面を開かずに **その場で完了／戻す**
- 予定には星なら★、保留なら「保留」
- **MONTH の各日は3件**：星付き → 設定した時間が長い順 → 時刻のない予定
- **PC のショートカット**：Tab で DAY → WEEK → MONTH → ‹ → 今日 → › を順に選び Enter で切り替え（Shift+Tab で逆）。DAY のダブルクリックで今日。N メモ、A 予定を追加、T 今日、D/W/M、←→
- スマホの下のボタン：メモ（メモを見る）／買い物／＋メモ（すぐメモ）／持ち物／予定
- PC の左メニュー：すぐメモの入力欄、予定を追加、メモを見る、買い物リスト、持ち物チェック、今日の振り返り、お知らせ、グループ、いつかやる（日付なし）、メンバー・共有設定、設定
- メモとお知らせの数は同じ見た目（コーラルの丸）

### 7.3 予定の入力（TaskEditor）
- 新しく入れるとき：タイトル、グループ、表示する人（共有グループ）、種類、日時、通知、繰り返し、詳細、色、★
- **一度入れた予定を開いたとき**：タイトルと詳細だけ。日時などを1行にまとめた「設定 ▼」で、ほかの設定を開く
- **種類を選ぶと通知が自動で入る**：会議＝30分前・5分前・時間ちょうど、当番＝前日20:00・30分前・時間ちょうど、一般／リマインダー＝時間ちょうど、買い物＝なし
- 種類は「＋ 種類を追加」でグループに足せる（メンバーで共有、アイコンなし）
- 繰り返し：なし／毎日／平日／毎週／毎月。その下に日〜土の曜日ボタン（押した曜日に毎週）。毎月は「○日」か「第n○曜日」。間隔と終了日
- 完了ボタンは入力画面にはない（ホームで完了する）

### 7.4 メモ
- すぐメモ（スマホは下の＋、PC は左上の入力欄）で、ひとことだけ記録（空でも可）
- メモを開くと「ひとこと」「詳細」だけ。「詳細に記録する」にチェックすると、ふつうの入力欄が出て予定になる
- **メモを見る**：付箋のボード。付箋を押すと開く。上の入力欄からも貼れる
- 何も書かずに保存したメモだけ、2分→5分→10分でお知らせ（10分は画面中央に大きく）
- メモがたまっていたら12時に1日1回お知らせ（プッシュ＋開いたときの付箋）

### 7.5 グループとメンバー
- グループを選ぶと上にメンバーのアイコン。下に「今やっている予定」か「次の予定」か「空き」。点の色：コーラル＝予定中、黄＝このあと予定、緑＝空き
- アイコンを押すと、カレンダーがその人の予定に切り替わり、**仕事の詳細カード**（いまやっていること・時間・あと何分・説明、次の予定、今日の完了数）を表示
- **カレンダーには自分あての予定だけ**。他の人の予定はアイコンから見る
- 予定の「表示する人」：共通／自分／〇〇さん（複数可）。新しい予定は自分だけが初期値。作成のお知らせとリマインドは表示する人にだけ
- 「自分だけ」の予定も、同じグループの人はアイコンから見られる（誰にも見せない予定は個人グループへ）
- 他の人の予定を見ているときに空き枠を押すと、その人あての予定として入力
- 既存の（表示する人を導入する前の）予定は共通のまま

### 7.6 買い物リスト（付箋のボード）
- リスト1枚が付箋1枚。付箋の右上に削除ボタン
- 品目は売り場ごと（野菜・果物 → 肉・魚 → 卵・乳製品 → 豆腐・練り物 → パン・米・麺 → 調味料 → 冷凍食品 → 飲み物・お菓子 → 日用品 → アウトドア → そのほか）に自動分類。いちばん長く一致した言葉で判定（「牛乳」は乳製品）
- 「卵 2パック」の数量はバッジで表示
- よく買うもの（2回以上買ったもの）をワンタップで追加
- 共有リストは「母がチェック」のように誰がチェックしたか表示
- 買い物モード（お店用の全画面、大きなチェック、残り数、その場で追加）
- テキストでコピー、チェック済みを片付ける、チェック済みは折りたたみ
- 全部チェックで自動完了 →「お店を出る時」チェックを表示
- 買い物リスト画面から作るリストは、グループでは共通

### 7.7 持ち物チェック（付箋のボード）
- チェックリスト1つが付箋1枚。付箋の中でチェック、編集、削除ボタン、全画面でチェック
- 表示のタイミング：決まった時間（曜日指定、時刻から2時間以内に開いたら全画面）／買い物のあと／自分で開く
- 最初から「家を出る時」「お店を出る時」を用意。チェックは毎日リセット

### 7.8 その日はじめて開いたとき（TodayBrief）
- ホームより先に、今日の予定を付箋で全画面表示。どこを触っても閉じる（PC はどのキーでも）。閉じ方の案内は出さない
- 端末ごと・人ごとに1日1回。通知から開いたときは出さない。朝の持ち物チェックはこのあと

### 7.9 完了しましたか？
- 終わる時間から30分たっても完了していない予定に確認（買い物・時刻なしは対象外）
- 複数あれば1つの画面にまとめる。各予定に完了／まだ／保留、下に「全部まだ」
- まだ → 15分後にもう一度、保留 → 以後聞かない
- 聞く相手：表示する人／共通なら作った人／個人グループなら持ち主
- プッシュ通知でも聞く（Android・PC は通知のボタンで答えられる。iPhone は通知を押すとアプリで聞く）

### 7.10 今日の振り返り
- アプリを閉じる瞬間に画面を出すことは、ブラウザの仕組み上できない。代わりに：
  - **17時以降に開いたとき**、その日1回だけ「今日の振り返りを見ますか？」（見る／そのまま閉じる／□今後はスキップする）
  - **17時から日付が変わるまで、お知らせの一番上** から開ける（見るまで未読に数える）
  - 夜20時にプッシュ通知でも案内（スキップの人には送らない）
  - 設定・左メニューからいつでも開ける。設定にスキップの解除
- 中身（付箋）：こなしたタスク（予定より5分以上早く完了すると褒めるバッジ）／仲間のがんばり（絵文字を送れる、送った絵文字はみんなの振り返りに数で表示）／今日登録したタスク／明日の予定
- ご褒美の演出：紙吹雪（1〜2個）→ クラッカー（3〜5個）→ クラッカー＋風船（6個〜）。動きを減らす設定では出さない

### 7.11 お知らせ・通知
- アプリ内の付箋（右上）：メンバーの作成（✨）・完了（🎉、絵文字で反応）・反応（💬）、メモがたまっている
- 時間のリマインド：開いている間は画面中央に大きく。閉じているときはプッシュ（cron が必要）
- サーバーが送る通知（`lib/notify.ts` の `runDueReminders`、毎分を想定）：時間のリマインド、何も書いていないメモ、12時のメモ、20時の振り返り、持ち物チェック、完了しましたか？

## 8. 画面の速さに関する仕組み

- **画面を先に書き換え、送信と取り直しは裏で**（`app/store.ts`）。`act(P.xxx(...), () => api(...))` の形で使う。失敗したら通知して最新に戻す
- 裏の取り直しは500msまとめて1回。取り直し中に画面を変えていたら、古い結果は捨てる（`changedSince`）
- 送信前の新しい予定・品目は仮のID（`tmp-...`）。仮IDのものは、サーバーで確定するまで開いたりチェックしたりできない（`isTmp`）
- 画面用データは1回の問い合わせ（`lib/state.ts`）。ログイン確認は60秒キャッシュ（`lib/auth.ts`）
- 最後のデータを localStorage に残し、次に開いたときはすぐ表示（ログアウトで消す）
- Service Worker が JS・CSS・フォントとページを保存（`public/sw.js`）。**ページ本体はまず最新を取りに行き**、3秒たっても返らない・つながらないときだけ保存したページを出す（以前は保存したページを先に出していたため、スマホのホーム画面アプリが古い画面のままになっていた）
- 公開ごとの版の印 `NEXT_PUBLIC_BUILD`（`next.config.mjs`。Vercel のコミットID）を画面とサーバーの両方に埋め込み、`GET state` が `build` で返す。画面の版と違えば、**開いたとき・アプリに戻ってきたときだけ** 自動で読み込み直す（入力の途中では読み込み直さない。同じ版では1回まで）
- `sw.js` の保存の仕方を変えたら `CACHE` の名前（今は `app-v2`）を上げる
- 表示中は20秒ごとに最新を取り直す（スマホとPCの同期）

## 9. 課題・次にやること

1. **毎分の通知の仕組みと Neon の無料枠（最優先）**
   - 今の作りで cron を毎分呼ぶと、毎回DBに問い合わせて Neon が眠らなくなり、無料プランの月100 CU時間を超えて **月末までDBが止まる恐れ** がある
   - 案：Upstash Redis（Vercel の Storage から無料で追加）に「次に送る通知の時刻」を置き、cron はそこだけ見て、時刻が来たときだけDBに問い合わせる。予定やメモを書き換えたらその値を消して計算し直す
   - そのあと cron-job.org で毎分 `https://todo-rho-navy-69.vercel.app/api/cron`（ヘッダー `Authorization: Bearer <CRON_SECRET>`）を設定する
2. Vercel の Function Region を Neon と同じ地域にする（`/api/health` で確認）
3. 自動テストがリポジトリにない（これまでは作業環境の一時ファイルで実行していた）。API のテストと Playwright の操作テストを `todo/tests/` に入れると安全
4. 「その日はじめて」の朝の画面と夕方の案内は **端末ごと** に1日1回（スマホとPCの両方で出る）。利用者が「どの端末でも1日1回」を望んだら、サーバーに記録する形に変える
5. iPhone のプッシュ通知は「ホーム画面に追加」して開いたときだけ届く（iOS の制限）
6. 実機（iPhone・PC）での本物のプッシュ通知は、cron を設定したあとに確認が必要

## 11. これまでの主な判断の記録

| 判断 | 理由 |
|---|---|
| 2台目の端末は6桁コードで追加 | 名前だけのログインだと、同名で入れない／他人も入れてしまうため |
| ログインは使うたびに180日延長 | 会社PCで毎週入り直す手間をなくす |
| 予定とタスクを1つの表に | 「会議」は予定でもありタスクでもあるため |
| 持ち物チェックは位置情報でなく時間と「買い物のあと」 | Webアプリは閉じている間に位置を見られないため |
| 「完了しましたか？」は終わる時間から30分 | 始まる時間からだと会議の途中で聞いてしまうため |
| 確認は1画面にまとめる | 夜に開いたとき、確認が何回も続かないように |
| 何も書いていないメモだけ段階的に知らせる | ひとことあればメモとして十分なため |
| 表示する人の初期値は「自分だけ」、既存の予定は共通のまま | 新しい考え方に合わせつつ、急に見えなくならないように |
| 振り返りは17時以降に開いたときと20時の通知 | 閉じる瞬間の画面はブラウザの仕組みで出せないため |
| PC の DAY は午前・午後の2列 | スクロールせずに1日を見渡すため（利用者の要望） |
