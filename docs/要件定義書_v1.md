## 1. コンセプト

**表向き**：ことばのカードを引いてお題を作り、「それってどんなモノ？」「何年にできそう？」を考えて、自分だけの発明を記録していくゲーム。記録した発明は、生まれる年の順に並んだ「発明年表」になる。

**裏の意図（画面には出さない）**：毎日の想像力を鍛える。ユーザーに「鍛える」というメッセージは一切伝えない。

| 仕掛け | ユーザーから見えるもの | ねらい |
|---|---|---|
| 伏せたカードから選ぶ | くじ引きの楽しさ | 偶然の組み合わせで、思い込みを外す |
| 「〇〇って、どんな〇〇？」 | お題への答え | 抽象的なことばを、具体的なモノに落とし込む |
| 「何年にできそう？」 | 年を決める遊び | 時間軸（未来・過去）で想像する |
| 発明年表 | 自分の発明が並ぶ年表 | 自分の想像の世界観が、形として残る |
| 発明No. | 通し番号 | ためていく楽しさ。続ける動機 |

## 2. 方針

1. **機能はできるだけ削る**。迷ったら入れない
2. **小学生でもわかるゲームにする**。ことばはやさしく、画面は少なく、ボタンは大きく。説明を読まなくても遊べる
3. **意図は隠す**。画面に「鍛える」「トレーニング」「成長」「上達」「スコア」「レベル」などは出さない。意図は、提出用の概要と面接で語る
4. **AIを使わない**。お題は決まったルールの乱数で作る
5. **データはブラウザの中だけ**。サーバーに送らない

## 3. 前作から引き継ぐもの・引き継がないもの

| 区分 | 内容 |
|---|---|
| 引き継ぐ（技術要件だけ） | 単一のHTMLファイル、vanilla JS、外部API・APIキー・バックエンドなし、localStorage に保存、表示する文字列はすべてエスケープ、イベントは addEventListener で登録、スマホ幅で全画面を操作できる、Vercel の静的配信 |
| 引き継がない | 見た目・質感・雰囲気（ワクログのニューモーフィズムや配色）、ひらめきワークのデモのコード。どちらも一から作る |
| 語のもと | ひらめきワークの単語（4品詞×18語。付録A）。まずこれでテストし、デモが動いてから各50語に増やす |

## 4. 画面と流れ

```
（初回だけ）なまえ → ホーム → 副詞 → 動詞 → 形容詞 → 名詞 → どんな〇〇？ → 何年？ → 発明できた！ → ホーム／発明年表
                     ホーム → 発明年表 → 発明のくわしい内容
```

### 4-1. なまえ（初回だけ）
- 「あなたのなまえは？」と聞く
- 入力欄は空欄で、中に薄く「あなたのなまえ」と表示する（プレースホルダー）
- 入力欄の下に「OK」ボタン。1文字以上入れると押せる
- 一度決めたら、この画面は出ない（なまえの変更機能は作らない）

### 4-2. ホーム
- タイトル「フューチャー日記」
- ボタンは2つ：「はじめる」「発明年表」
- これまでの発明の数を、さりげなく表示してよい（例：「これまでの発明：12」）。必須ではない

### 4-3. カードを選ぶ（4回）
- 副詞 → 動詞 → 形容詞 → 名詞 の順に、品詞ごとに1枚ずつ選ぶ
- 各品詞の語のプール（最終的に50語）から、**3枚を伏せて**並べる
- 1枚を選ぶと、そのカードだけ表になる。**残りの2枚は見せない**
- 引き直し（シャッフル）はない
- どの品詞を選んでいるかは、見て分かるようにする（色・ラベル・進み具合など。表現は実装時に決める）

**語の出し方**
- 直近に出た語は、出にくくする（同じようなお題が続くと飽きるため）
- 品詞どうしで、意味や語が重なる組み合わせも避けたい（例：「かわる」と「かえる」が同じお題に並ぶ、など）。どこまでやるかは実装時に検討する

### 4-4. お題ができる
- 4枚をつなげてお題にする。例：「おそるおそる隠れるステキないす」
- つなげ方は「副詞＋動詞＋形容詞＋名詞」をそのまま並べる（区切りは実装時に見やすく調整してよい）

### 4-5. どんな〇〇？
- 「『おそるおそる隠れるステキないす』って、どんな**いす？**」のように、最後の名詞に「？」を付けて聞く
- 自由入力（1文字以上で次へ進める）

### 4-6. 何年にできそう？
- 「その**いす**って、何年にできそう？」と聞く
- 年を整数で入力する。未来の年が多いはずだが、**過去の年も入れてよい**（例：1980年。「実はもうある」も遊びのうち）
- 入力のしかた（数字の入力欄か、＋−ボタンか）は、小学生でも迷わない形を実装時に決める。入れられる範囲は 1〜9999年 を目安とする

### 4-7. 発明できた！
- 発明No.を付けて記録したことを伝える。例：「発明No.12 ができた！」
- ボタン：「発明年表を見る」「ホームへ」

### 4-8. 途中でやめたとき
- お題づくり（4-3〜4-6）の途中でホームに戻ろうとしたら、「やめると、この発明はのこりません」と確認する
- やめた場合、書きかけは保存しない

### 4-9. 発明年表
- 記録した発明を、**生まれる年の古い順**に並べる
- 年表の範囲は、記録された年の**最小から最大まで**。例：2024年と2034年の発明があれば 2024〜2034年。1件だけ（2030年）なら 2030年だけ
- 同じ年の発明は、記録した順に並べる
- 「いま」（今年）の位置に線を引く。今年より前と後が分かるようにする
- 1件ずつ、次の一文で表示する
  > **2030年**　りょうだい が「おそるおそる隠れるステキないす」を発明する
  - 「〇〇」には、お題の4語をそのまま入れる
  - 今年より前の年は「発明した」にしてもよい（実装時に判断）
- 発明がまだないときは、「まだ発明がありません。『はじめる』から作ってみよう」のように案内する

### 4-10. 発明のくわしい内容
- 年表の1件を押すと開く
- 表示する内容：発明No.、お題（4語）、「どんな〇〇？」への答え、生まれる年、記録した日時、なまえ
- 編集・削除はできない

### 4-11. 作らないもの（オミット）
- 発明の編集・削除
- データの書き出し・読み込み（JSON）、端末の移行
- なまえの変更
- 語の編集・枚数の設定（ひらめきワークにはあったが、今回は固定）
- カードの引き直し、選ばなかったカードの表示
- 1日の回数の制限（何回でも遊べる）
- 書いた日順の一覧（日記の面）。記録日は詳細に残す
- 続きの発明（派生）
- 共有、アカウント、サーバー

## 5. データ構造

```
AppData {                       // localStorage のキー：future-nikki.v1
  version: 1
  userName: string              // 初回に入力
  inventions: Invention[]
  recentWords: {                // 直近に出た語（出にくくするため）
    adverb: string[], verb: string[], adjective: string[], noun: string[]
  }
}

Invention {
  no: number                    // 発明No.（1から連番）
  words: { adverb, verb, adjective, noun }   // 選んだ4語
  description: string           // 「どんな〇〇？」への答え
  year: number                  // 生まれる年（整数）
  createdAt: string             // 記録した日時（ISO）
}
```

- 発明No.は、記録した順の連番。削除がないので欠番は出ない
- 年表の並びは year の昇順、同じ年は createdAt（または no）の昇順
- 語のプールはコード内の定数（4品詞 × 最終50語）。ユーザーは編集しない
- 保存に失敗したとき（容量超過など）は、画面に知らせる

## 6. 語のプール

- 現段階：ひらめきワークの4品詞×18語（付録A）でテストする
- デモが動いたあと：各品詞を50語に増やす。追加の32語×4品詞の案は、開発者とClaudeで一緒に決める
- 選び方の基準（案。実装時に確定）
  - 名詞：身近で、形のあるモノ（発明しやすい）
  - 形容詞：人の性格や様子を表すことば（例：几帳面な、無邪気な）。モノに人格が出て面白くなる
  - 動詞・副詞：意味が重ならないようにする
  - すべて：小学生にも読めて意味が分かる。ネガティブすぎる語、差別的な語は入れない

## 7. 技術要件

- 単一のHTMLファイル（vanilla JS）。外部ライブラリは原則使わない
- 外部通信・AIなし
- 保存は localStorage。読めない・壊れたデータでも画面が壊れない
- 表示する文字列（なまえ、答えの文章）はすべてエスケープする。`innerHTML` へのそのままの埋め込みはしない
- イベントは addEventListener で登録する（onclick 属性は使わない）
- スマホ縦向き（390px程度）を主に設計する。PCでも崩れない
- 最新の Safari（iPhone）と Chrome で動く
- 公開は Vercel の静的配信。公開作業は開発者が行う

## 8. 受け入れ基準

1. 初回に「あなたのなまえは？」が出て、入力して OK を押すとホームに進む。2回目以降は出ない
2. 「はじめる」から、副詞→動詞→形容詞→名詞の順に、伏せた3枚から1枚ずつ選べる。選んだカードだけが表になり、残りの2枚は見えない
3. 4語のお題が表示され、「〇〇って、どんな〇〇？」に答えられる
4. 「その〇〇って、何年にできそう？」で、過去・未来を問わず年を入れられる
5. 記録すると、発明No.が連番で付く
6. 発明年表に、生まれる年の順で「20XX年　なまえ が「お題」を発明する」と並ぶ。範囲は記録された年の最小〜最大。同じ年は記録した順。「いま」の線がある
7. 年表の1件を押すと、詳細（No.・お題・答え・年・記録日時・なまえ）が見られる
8. 途中でホームに戻ると確認が出て、やめた場合は何も残らない
9. 直近に出た語が、すぐには出にくい
10. なまえや答えに `<script>` などを入れても実行されない
11. スマホ幅で、すべての画面を操作できる
12. 画面に「鍛える」などの意図を表すことばが出ない。小学生でも説明なしで遊べる
13. AIや外部APIを呼ぶ処理が一切ない

## 9. 実装時に決めること

1. 品詞どうしの重なりを、どう避けるか（4-3）
2. 「直近に出た語」をいくつまで覚えるか、どれくらい出にくくするか
3. 年の入力のしかた（4-6）
4. 今年より前の年を「発明した」と表すか（4-9）
5. 画面の見た目（色・カードの演出・フォント）。前作は引き継がない
6. アプリ名は「フューチャー日記」に決定（2026-10-27）。遊びの中心は発明なので、「発明年表」「発明No.」「発明できた！」などの表記に「発明」を残す。公開前に、同名のアプリや作品がないかを確認する
7. 50語への拡張（デモが動いてから）

## 10. 提出用の概要（たたき台。最後に詰める）

1. **誰のどんな課題**：日々の中で、新しいことを想像する機会が少ない人。想像力は使わないと衰えるが、「鍛えよう」と言われると続かない
2. **どんな価値**：ことばのカードを引いてお題を作り、「どんなモノ？」「何年にできそう？」を考えるだけで、自分だけの未来の発明が年表として残っていく。遊んでいるうちに、抽象を具体にする力と、時間軸で考える力が自然に使われる（意図は画面に出さず、ゲームとして設計した）
3. **ビジネスモデル（仮説）**：個人は無料。学校・研修・ワークショップ向けに、語のセットやお題の共有を有料で提供する案などを検討する
