## 0. 「どんなアプリか、簡単に紹介してください」と言われたら

### 30秒版（まず何をするアプリか）

発明日記は、ことばのカードを引いてできた不思議なお題から、未来の発明を考えて記録していくアプリです。
カードを4枚引くと、「こっそり光る几帳面な図書館」のようなお題ができます。それがどんなモノで、何年にできそうかを考えます。
考えた発明は、記録した順ではなく、生まれる年の順に並んで、自分だけの未来年表になっていきます。
この疑似的なひらめきを通して発想力を伸ばし、自信につなげることがねらいです。

### 1分版（なぜ作ったかまで）

私はワークショップで、ランダムな単語カードを使った発想ツールを作り、使ってきました。
仕事では発想力が求められるのに、発想のしかたを学んだ人はほとんどいません。だから「自分はできない」と思い込んでいる人が多い。でも、ワークショップではそういう人も、実際にアイデアを出せるようになります。
ただ、ワークショップはその回限りです。そこで、このツールを1人で毎日遊べるようにしたのが、発明日記です。
カードを4枚引くと、「こっそり光る几帳面な図書館」のようなお題ができます。単語の意味は分かるのに、文の意味が分からない。そのギャップを埋めようと、自然と頭が考え始めます。
考えた発明は、生まれる年の順に並んで、未来年表になっていきます。
「鍛える」とは言わずに、遊んでいるうちに、気づいたら発想力が鍛えられていた。それを目指したアプリです。

> 使い分け：最初に「簡単に」と言われたら30秒版。「作った背景も含めて」なら1分版。画面を見せながら話せるなら、お題の例は実際に引いたものに差し替える

### 「このアプリの価値は何ですか？」と聞かれたら

**一言で**：発想のしかたを学んだことがない人でも、毎日数分、遊びながら「自分でもアイデアを出せた」という体験を積み重ねられることです。

**3つに分けると**
1. **誰でも発想が始まる**：単語の意味は分かるのに、文の意味が分からない。そのギャップを埋めようと、才能や経験に関係なく頭が勝手に考え始める
2. **続けられる**：「鍛える」とは言わず、ゲームとして遊べる。アイデアを書かなくても進めるので、手が止まらない
3. **できたことが見える**：発明が年表に積み上がり、「こんなに考えられた」が目に見える。それが自信になる

**ほかの方法との違い**：本やセミナーは1回学んで終わり。ブレストのツールは、もともとアイデアが出せる人向け。発明日記は、苦手な人が毎日1人で続けられる

## 1. 話の背骨（最初の1分で話す流れ）

1. **きっかけ**：【自分が「発想力」に悩んだ場面、またはひらめきワークで見たこと】
2. **課題**：発想力を鍛えたい会社員は多い。けれど、何をすればいいか分からず、学んでもその場限りで習慣にならない
3. **着目点**：「鍛えよう」とすると続かない。だから、鍛えると言わずに、毎日つい触ってしまう遊びにした
4. **仕組み**：伏せたカードで作る「読めるのに正体が分からないお題」。人は分からないものを分かろうとする。その境目で発想が動く
5. **ログとしての形**：記録は日付ではなく「生まれる年」で並ぶ「発明年表」。自分の想像の世界が積み上がって見える
6. **これから**：個人で続くかを確かめ、コンテストや発明SNSへ広げる

> 練習：この6つを、何も見ずに1分で話せるまで声に出す

### D. AIの使い方

| 質問 | 答えの材料 | 自分の言葉 |
|---|---|---|
| AIをどう使って作ったか | 先に要件定義書を作り、段階ごとに Claude Code に実装させた。見た目の方向性、単語の候補出し、テスト、文章の整理を任せた。採否は自分で決めた | （11/04 練習）アプリの概要を伝えて、AIに実装させた。単語の選定にもAIを使ったが、入れるか否かは自分で判断した。→（2回目）コンセプトや方針を書いた定義書をAIに渡し、画面の流れ・単語の選定基準・段階ごとの計画案を確認してから、一段階ずつ実装した。AIが作ったもの・選んだものに対して、遊んで違和感がある箇所や判断が必要な箇所は、AIに判断させず、自分がどう思ったかで決めた。誰の課題か、どう解決するかという根っこは自分で掘り下げた。【例を1つ足す】 |
| AI前提の会社なのに、なぜアプリにAIを入れなかったのか | AIがお題や答えを出すと、考えるのがAIになってしまう。このアプリの価値は「自分で考える時間」にある | （11/04 練習）あくまで自分が主体となって空想力を伸ばし、自信をつけてもらうため。お題も、本来は3枚から選ばせずに完成したお題を出してもいいが、それだと主体性は生まれない。「このカードは自分が選んだ」という事実があるだけで、主体的な思考モードになる。アプリの中で主体的に考えてもらうことを重視した |
| 採用しなかったAIの提案は | 「AIの案を採らなかった・変えた例」から1つ。AI → 自分の違和感 → 理由 → 結果の順 | （11/04 練習）AIは当初、年表を古い年が上になる向きにしていたが、未来の年表なので、あえて下から積み上がる向きに変えた。【理由を一段深く：未来が上へ伸びていく／発明が積み上がって見える】 |
| AIに任せなかったこと | 何を作るか、誰に届けるか、単語の採否、触ってみて違和感のあるところの判断 | 【　】 |

**AIとの進め方の事実（この開発で実際にやったこと）**

1. **要件定義書を先に書いた**：コンセプト、方針（機能は削る・意図は隠す・AIを使わない）、画面の流れ、データ構造、受け入れ基準、段階ごとの実装計画。実装はAIに計画を出させ、確認してから段階ごとに進めた
2. **段階1〜3は家のPCで、そのあとは Claude Code（クラウド）で**：スチームパンク化、年表と詳細画面、単語の拡張、細かい調整
3. **AIに任せたこと**：実装、見た目の案、単語の候補出し（各50語＋サービス35語）、動作テスト（スクリーンショット、お題づくり5000回の自動確認）、要件定義書の更新、提出文の整理、面接の壁打ち
4. **自分で決めたこと**：誰の何の課題か、意図を隠す方針、アプリ名、世界観（スチームパンク）、単語の採否、動詞の過去形とサービス名詞を足す発想、年表の向き、入力の任意化、±1ボタンの削除
5. **回し方**：AIが作る → 自分が実際に遊ぶ → 違和感を一言で伝える → すぐ直る。例：カードの表示時間を1秒→0.7→0.5→0.3→0.2秒と、触りながら詰めた
6. **AIの案を採らなかった・変えた例**：
   - 年表は古い年が上 → 下が過去・上が未来に逆転（積み上がる感覚）
   - タイトルの4色 → ダークグレー一色
   - 「±1」ボタン → 削除（機能が余分）
   - アイデア入力は必須（要件定義書の初版）→ 任意に（見るだけでも発想は起きる）
   - 単語候補（各50語・サービス35語）→ 食器・スマホを外し、サービスは35語から8語だけ採用、カフェ・レストランは自分で追加
   - 「これからする発明の数」は今年以降だけ数える案 → 採らなかった
7. **AIに気づかされたこと**：「宅急便」は登録商標なので「宅配便」に／動詞の多義語（かえる・おさめる）のあいまいさ／`docs` が公開されてしまう問題

## 3. こだわりの記録（触って直したところ）

面接で「どこにこだわったか」と聞かれたときの具体例。**「何を変えたか」より「なぜ変えたか」を話す**

| 変えたこと | なぜ |
|---|---|
| 画面に「鍛える」「スコア」「レベル」を出さない | 意図が見えると構えて続かない |
| 伏せたカードから選び、選ばなかったカードは見せない | 比べて選ぶと、いつもの発想に戻る |
| アプリにAIを使わない | 考えるのは自分。AIが考えると価値がなくなる |
| アプリ名を「フューチャー日記」→「発明日記」 | 遊びの中心が「発明」だから |
| 品詞をまたいで意味が重なる組み合わせを出さない（うとうと×眠る など） | お題がただの説明になって、分からなさが消える |
| 動詞に過去の形を足した（隠れる／隠れた） | 同じ語でもお題の物語が変わる。バリエーションが増える |
| 名詞にサービスを足した（保険・宅配便・SNS など） | モノだけでなく、コトの発明も考えられるように |
| 単語は50語にこだわらず、発想が広がるかで選んだ | 数よりお題の質 |
| カードをめくった後の表示時間を1秒→0.2秒 | テンポ。選んだ語は上の枠に残るので、長く見せなくてよい |
| 年表を下が過去・上が未来に | 発明が積み上がっていく感覚 |
| アイデアの入力を任意に（空なら確認だけ出す） | 見るだけでも発想は起きる。書けない人を止めない |
| 「±1」ボタンを消した | 機能が余分。細かく変えたい人は数字を直接入力できる |
| 名前画面の見出しを消した | 入力欄の表示だけで伝わる。画面の要素は少なく |
| 「これまでの発明」→「これからあなたがする発明の数」 | 発明は未来に生まれるもの |

## 4. 突っ込まれやすいところ（先に答えを持っておく）

1. **実際に誰かに遊んでもらったか**：まだなら、面接までに2〜3人に遊んでもらい、反応を1つ話せるようにすると強い
2. **ワクログをやめた理由**：必ず聞かれる
3. **対象が小学生 → 高校生以上 → 会社員と変わった理由**：迷った過程そのものを、考えた跡として話せる
4. **ビジネスモデルの詰めの甘さ**：「仮説です」と言ったうえで、まず何を確かめるかを話す
